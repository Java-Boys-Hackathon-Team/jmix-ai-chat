# Сценарий видео: Structured Output

## План наполнения

Идем по проекту постепенно:

1. Коротко объясняем, что такое structured output.
2. Показываем UI.
3. Разбираем `ResumeParserView`.
4. Переходим в сервис работы с LLM.
5. Показываем парсинг файла.
6. Показываем DTO как контракт structured output.
7. Добавляем объяснение "со стороны ИИ": что модель получает, что должна вернуть, почему это не просто текст.

## 1. Что такое Structured Output
Когда мы обычно работаем с LLM, мы часто получаем обычный текст: ответ в чате, пояснение, список идей, какой-то markdown.

Но в бизнес-приложениях нам часто нужен не текст, а данные, которые можно сразу положить в поля формы, сохранить в базу или передать дальше по процессу.

Structured Output, или структурированный вывод, - это возможность LLM генерировать ответы в строго заданном машинно-читаемом формате, например в JSON, в соответствии с предоставленной схемой.

Если сказать проще: мы даем LLM промпт с текстом, который нужно распарсить или обработать, и схему, на основе которой нужно сформировать ответ. Обычно это JSON Schema.
После этого LLM возвращает ответ, который соответствует этой схеме, то есть валидный JSON с нужными полями и типами.


Например, если у нас есть резюме, нам не нужен ответ в стиле: "Кандидат выглядит опытным Java-разработчиком". Нам нужны конкретные поля:

- ФИО;
- email;
- телефон;
- желаемая позиция;
- навыки;
- опыт;
- образование.

Structured output - это как раз подход, когда мы просим модель вернуть ответ не свободным текстом, а в заранее заданной структуре.

В нашем случае такой структурой будет Java-класс `ResumeFormData`. Мы описываем, какие поля хотим получить, а Spring AI помогает превратить ответ модели в обычный Java-объект.

То есть главная мысль:

> Structured output - это способ использовать LLM не как генератор текста, а как источник типизированных данных для приложения.

И дальше я покажу это на практическом сценарии: загружаем PDF-резюме, модель извлекает из него данные, а Jmix-форма заполняется автоматически.

## 2. UI

Сначала покажу сам экран. Здесь у нас очень простой интерфейс: есть кнопка загрузки резюме и набор полей формы.

Пользователь загружает файл с резюме, а дальше форма заполняется автоматически: ФИО, позиция, email, телефон, город, краткое описание, навыки, опыт и образование.

Важная мысль здесь такая: мы не просим AI просто написать ответ текстом. Мы хотим, чтобы AI помог заполнить конкретную бизнес-форму в Jmix.

## 3. `ResumeParserView`

Теперь перейдем в `ResumeParserView`. Это контроллер экрана, который реагирует на загрузку файла.

В Jmix экран обычно состоит из двух частей: XML-дескриптора и Java-контроллера.

В XML мы описываем, какие компоненты есть на экране: upload, поля ввода, layout. В нашем случае upload-компонент объявлен в `resume-parser-view.xml` с id `resumeUpload`.

А в Java-контроллере мы описываем поведение этого экрана. Аннотация:

```java
@Subscribe("resumeUpload")
```

говорит Jmix: вызови этот метод, когда у компонента `resumeUpload` произойдет событие изменения значения.

Здесь есть обработчик загрузки:

```java
@Subscribe("resumeUpload")
public void onResumeUpload(AbstractField.ComponentValueChangeEvent<FileStorageUploadField, FileRef> event) {
    uploadedFileRef = event.getValue();

    if (uploadedFileRef != null) {
        parseUploadedResume();
    }
}
```

Когда пользователь загружает файл, Jmix кладет в событие значение типа `FileRef`.

`FileRef` - это не сам файл в памяти, а ссылка на файл внутри Jmix FileStorage. То есть Jmix уже принял файл, сохранил его в свое файловое хранилище, а нам отдал абстракцию, через которую этот файл можно потом открыть.

Мы сохраняем эту ссылку:

```java
uploadedFileRef = event.getValue();
```

И дальше передаем ее в метод разбора:

```java
parseUploadedResume();
```

Внутри `parseUploadedResume()` мы передаем `uploadedFileRef` в сервис работы с LLM:

```java
ResumeFormData data = resumeStructuredOutputService.extractFromDocument(uploadedFileRef);
```

И это важная граница ответственности. `ResumeParserView` сам не парсит документ и не общается с моделью. Он просто передает ссылку на файл в `ResumeStructuredOutputService`.

А вот этот сервис уже занимается основной работой: берет файл, достает из него текст, отправляет этот текст в LLM и просит модель вернуть данные в структурированном виде. К нему мы перейдем дальше.

То есть ответственность экрана здесь минимальная:

- получить ссылку на загруженный файл;
- передать файл в сервис;
- взять результат;
- заполнить поля формы.

После того как сервис вернул `ResumeFormData`, мы просто раскладываем данные по полям:

```java
fullNameField.setValue(valueOrEmpty(data.getFullName()));
positionField.setValue(valueOrEmpty(data.getPosition()));
emailField.setValue(valueOrEmpty(data.getEmail()));
phoneField.setValue(valueOrEmpty(data.getPhone()));
cityField.setValue(valueOrEmpty(data.getCity()));
```

Для списков, например навыков, опыта и образования, используются небольшие helper-методы форматирования. Они нужны только для удобного отображения в UI, поэтому подробно на них останавливаться не будем.

Главное здесь: экран не знает, как работает AI, не знает, как парсится PDF, и не пытается сам доставать данные из документа. Он просто запускает сценарий и показывает результат.

## 4. `ResumeStructuredOutputService`

Теперь переходим в `ResumeStructuredOutputService`. Это сервис, где уже начинается работа с LLM.

Снаружи у него один главный метод:

```java
public ResumeFormData extractFromDocument(FileRef fileRef)
```

Он делает несколько шагов:

1. Достает текст из загруженного файла.
2. Извлекает основной объект `ResumeFormData`.
3. Отдельно извлекает список навыков.
4. Отдельно классифицирует уровень кандидата через enum.
5. Возвращает готовый объект для заполнения формы.

В коде это выглядит так:

```java
String documentText = documentTextExtractor.extract(fileRef);

ResumeFormData formData = extractResumeFormData(fileRef.getFileName(), documentText);
formData.setSkills(extractSkills(documentText));
formData.setSeniority(classifySeniority(documentText));
```

Здесь удобно показать, что structured output - это не только один Java-объект.

### Объект

Основной пример - это объект:

```java
.entity(ResumeFormData.class)
```

Мы описали Java-класс `ResumeFormData`, и Spring AI пытается вернуть ответ модели сразу как объект этого класса.

### Коллекция

Для навыков можно показать отдельный пример со списком:

```java
.entity(new ParameterizedTypeReference<List<String>>() {})
```

Это полезно, когда нам нужен не весь объект резюме, а конкретная коллекция: например, только список навыков без дублей.

Почему здесь не `List<String>.class`? В Java generics стираются во время выполнения. То есть в runtime у нас нет нормального `List<String>.class`, есть только общий `List.class`, и информация про `String` теряется.

Поэтому для таких случаев используется `ParameterizedTypeReference<List<String>>`. Он сохраняет информацию о полном типе: не просто "какой-то список", а именно список строк.

Здесь есть важный нюанс: если мы просим `.entity(new ParameterizedTypeReference<List<String>>() {})`, то ответ модели должен быть именно JSON-массивом верхнего уровня:

```json
["Java", "Spring Boot", "PostgreSQL"]
```

А вот такой ответ уже не подойдет:

```json
{
  "skills": ["Java", "Spring Boot"]
}
```

Потому что это уже объект, а не список. Поэтому в prompt мы явно пишем: "верни JSON-массив строк верхнего уровня, не объект с полем skills".

Можно сказать так:

> Для обычного класса мы пишем `.entity(ResumeFormData.class)`, а для коллекции с generic-типом используем `ParameterizedTypeReference`, чтобы Spring AI понимал, что нам нужен именно `List<String>`.

### Enum

Еще один хороший пример - классификация через enum:

```java
.entity(ResumeSeniority.class)
```

Мы заранее ограничиваем возможные значения:

```java
INTERN, JUNIOR, MIDDLE, SENIOR, LEAD, UNKNOWN
```

И модель должна выбрать одно из них. Для бизнес-приложений это удобно, потому что дальше в коде мы работаем не со строкой "примерно senior", а с конкретным enum-значением.

## Черновик формулировки

Можно сказать так:

> На уровне UI у нас все выглядит как обычная Jmix-форма. Пользователь загружает резюме, Jmix дает нам `FileRef` - ссылку на загруженный файл. Мы передаем эту ссылку в сервис, который уже достает текст из документа, вызывает LLM и возвращает структурированный Java-объект. А дальше мы просто заполняем поля формы из этого объекта.

## 5. Что показать в логах

В логах лучше не показывать весь запуск приложения: Spring Boot, Vaadin, Liquibase и security-шум не относятся к structured output.

Нужно сфокусироваться на логах `SimpleLoggerAdvisor`, потому что там видно самое важное:

```text
request: ChatClientRequest ...
response: ...
```

На что обратить внимание:

1. В `request` видно system prompt и user prompt. То есть видно, какой текст мы отправили в модель.

2. В `context` видно строку:

```text
spring.ai.chat.client.output.format=Your response should be in JSON format...
```

Это хороший момент для объяснения: Spring AI сам добавляет инструкции для structured output.

3. Там же видно JSON Schema:

```json
{
  "type": "object",
  "properties": {
    "fullName": { "type": "string" },
    "experience": { "type": "array" },
    "seniority": {
      "type": "string",
      "enum": ["INTERN", "JUNIOR", "MIDDLE", "SENIOR", "LEAD", "UNKNOWN"]
    }
  }
}
```

Это можно подсветить словами:

> Вот здесь видно, что наш Java-класс превратился в JSON Schema, которую Spring AI передает модели как формат ожидаемого ответа.

4. В `response` видно, что модель вернула валидный JSON:

```json
{
  "fullName": "Гулямов Рустам Кисматуллоевич",
  "position": "Java-разработчик",
  "experience": [...]
}
```

5. Для коллекции надо показать отдельный request, где схема уже не object, а array:

```json
{
  "type": "array",
  "items": {
    "type": "string"
  }
}
```

И response:

```json
["Java", "PostgreSQL", "Docker"]
```

6. Для enum надо показать схему:

```json
{
  "type": "string",
  "enum": ["INTERN", "JUNIOR", "MIDDLE", "SENIOR", "LEAD", "UNKNOWN"]
}
```

И response:

```json
"MIDDLE"
```

Важное предупреждение для записи: в логах видны персональные данные из резюме - email, телефон, ФИО. Перед публикацией лучше использовать тестовое резюме или замазать чувствительные данные.
